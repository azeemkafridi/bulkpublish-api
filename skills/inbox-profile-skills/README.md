# Inbox-profile skills

<!-- Generated from skills/src in the bulkpublish-api repository. Edit the source there, not this copy. -->

Skills that need tools the `inbox` profile adds to core: the Inbox and comment replies, best posting times, compared-with-usual figures, metric history, link clicks, saved replies, repeat posts and bulk actions. The hosted connector at `mcp.bulkpublish.com/mcp` serves this profile (`BULKPUBLISH_TOOL_PROFILE=inbox`). Ship them beside `../core-profile-skills` to a connector running it, never to one running `core`.

Every file here is generated from `../src`. Edit the source and run `cd mcp-server && npm run build:skills`; `npm run check:skills` fails on a copy that differs, on a tool the profile does not serve, and on a post type or parameter the server does not accept.

| Skill | What it is for |
|---|---|
| [`best-time-scheduling`](best-time-scheduling/SKILL.md) | Find the weekdays and hours when the user's BulkPublish posts get the most engagement, and schedule or move posts into those times, falling back to the queue when there is not enough history. Use when the user asks when to post, the best time to post, or wants posts scheduled at good times. |
| [`comment-replies`](comment-replies/SKILL.md) | Read the comments on a published BulkPublish post and reply to, like, hide or delete them, with a confirmation before anything is posted or removed. | [`inbox-triage`](inbox-triage/SKILL.md) | Read, sort and answer the BulkPublish Inbox (direct messages, reviews, comment threads and mentions) with a confirmation before every reply, and keep team notes, labels and saved replies. | [`mention-monitoring`](mention-monitoring/SKILL.md) | Keep track of posts by other people that mention the user's connected accounts in the BulkPublish Inbox, sort them, flag them for the team, and answer the ones worth answering after the user confirms. | [`next-week-plan`](next-week-plan/SKILL.md) | Plan and prepare next week's BulkPublish posts from what worked over the last 30 days, schedule them at the account's best times, and leave everything as drafts or approval requests until the user says go. Use when the user wants canned or template replies, a reply library, or keeps answering the same questions. |
